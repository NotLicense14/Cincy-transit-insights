# ============================================================================
# GO-METRO-INSIGHTS cron block — source of truth for the live crontab.
# ============================================================================
#
# Install with:   scripts/install-crontab.sh
# (safe marker-merge — replaces only this block, never your other cron jobs.)
#
# Bus detection, recaps, health audits, reference-data refresh, web-data
# publish, and backups all run here. Go-Metro is bus-only — no train or Metra
# jobs.
#
# The /path/to/metro-insights placeholder is filled in at install time
# (cron does NOT expand variables in R= lines — the install script inlines it).
# Logs go to cron/<name>-cron.log (gitignored).

# GO-METRO-INSIGHTS-START

# All jobs run via bin/cron-run.sh <log-name> <script> [args...] which handles
# cd, timestamping, and log redirection.
R=/path/to/metro-insights/bin/cron-run.sh

# --- Buses ---
# cross-route pileup (2+ routes at one corner). Runs 1 min BEFORE bus-bunching
# so a posted multi-route pileup suppresses the per-route post for the same
# buses (recentCrossBunchMemberIds, 10-min window).
0-59/20 *  *  *  *   $R bus-cross-bunching bin/bus/cross-bunching.js
1-59/20 *  *  *  *   $R bus-bunching     bin/bus/bunching.js
# bus-alerts on even minutes, bus-pulse on odd minutes — same threading-
# safety reasoning: when both run on the same minute they each see "no thread
# parent yet" and post separate top-level posts instead of replying to each other.
0-58/2  *  *  *  *   $R bus-alerts       bin/bus/alerts.js
1-59/2  *  *  *  *   $R bus-pulse        bin/bus/pulse.js
6-59/20 *  *  *  *   $R bus-gaps         bin/bus/gaps.js
# bus-thin-gaps: gap detection for low-frequency routes, every 15 min on a :13
# offset so it doesn't share a wall minute with bus-gaps (:06/26/46) or the
# pulse/alerts cadence.
13-58/15 *  *  *  *  $R bus-thin-gaps    bin/bus/thin-gaps.js
0       */2 *  *  *  $R bus-speedmap     bin/bus/speedmap.js
7       *  *  *  *   $R bus-ghosts       bin/bus/ghosts.js
# observe-buses runs every minute. Go-Metro refreshes vehicle positions every
# 30s, so 60s misses at most one refresh cycle. bunching/gaps/pulse all read
# the cache (maxStaleMs=90s) so observe-buses is the only feed-poll site for
# the all-routes workload.
*       *  *  *  *   $R observe-buses    scripts/observeBuses.js
# incident-roundup runs every 5 min on :04 offset, separate from pulse :02 /
# alerts :02 / gaps :07 so its detector-correlation read isn't racing the writers.
4-59/5  *  *  *  *   $R incident-roundup bin/incident-roundup.js

# --- Recaps ---
20      10 *  *  0   $R bus-recap        bin/bus/recap.js   --window=week
30      10 1  *  *   $R bus-recap        bin/bus/recap.js   --window=month

# --- Health audits ---
*/30    *  *  *  *   $R audit-alerts     bin/audit-alerts.js

# --- Reference data refresh ---
15      3  *  *  *   $R fetch-gtfs       scripts/fetch-gtfs.js
0       4  1  *  *   $R fetch-signals    scripts/fetch-signals.js

# --- Web data publish ---
# Publishes alerts.json + daily-counts.json to the data origin and fires a
# rebuild when data changed. Also invoked event-driven by webPushTrigger.js
# ~30s after a new post. No-ops on byte-identical data.
*/15    *  *  *  *   GO_METRO_INSIGHTS=/path/to/metro-insights /bin/sh /path/to/metro-insights/bin/push-web-data.sh >> $HOME/metro-alert-history/cron/push-web-data-cron.log 2>&1
# export-event-tracks: archive per-incident vehicle-position tracks for the
# event-page replay. Offset to :09 so it runs after the :00/:15 push refreshes
# alerts.json. See docs/REPLAY.md.
9-59/15 *  *  *  *   $R export-event-tracks bin/export-event-tracks.js

# --- Backups ---
17      4  *  *  *   /path/to/metro-insights/scripts/backup-db.sh >> /path/to/metro-insights/cron/backup-db-cron.log 2>&1

# GO-METRO-INSIGHTS-END
